# Принятые решения

Решения недели 1, зафиксированные до начала реализации.

| № | Вопрос | Решение | Причина |
|---|--------|---------|---------|
| 1 | Хранение денег в SQLite | Тип `decimal` везде; суммы считаются в памяти после выборки | SQLite хранит `decimal` как текст и не выполняет `SUM` в SQL; объёмы малы (10 000 операций по ТЗ). При проблемах со скоростью переход на копейки (`long`) |
| 2 | Сообщения об изменениях (Observer) | `IMessenger` из CommunityToolkit.Mvvm используется прямо в слое Application | Не нужно писать собственную шину событий |
| 3 | Работа с базой в сервисах | `IUnitOfWorkFactory` создаёт один `IUnitOfWork` на одну операцию; транзакция на нём | Контекст живёт одну операцию (нет устаревших данных на экранах); атомарность сделок |
| 4 | Версия платформы | Проекты собираются на `net11.0` (`net11.0-windows` для Wpf и тестов); в ТЗ указан .NET 10 | Установлен SDK 11. Расхождение нужно согласовать с руководителем |
| 5 | Предупреждение NU1701 | Отключено в `FinTrack.Wpf` и `FinTrack.UnitTests` | Зависимости LiveCharts2 (OpenTK, SkiaSharp.Views.WPF) собраны под .NET Framework; на современном .NET работают |
| 6 | Класс приложения WPF | В `App.xaml.cs` указывается `System.Windows.Application` | Конфликт имени с пространством имён слоя `Application` |
